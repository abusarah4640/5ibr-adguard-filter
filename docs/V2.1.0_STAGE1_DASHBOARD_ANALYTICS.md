# v2.1.0-stage1 Dashboard Analytics Foundation

## Goal

Add a read-only analytics foundation to the existing dashboard using only
current project data. This is a stage build, not a stable v2.1.0 release.

## Data sources

- Domain statistics use the rows already returned by `load_database()`.
- Operational cards use the append-only Web audit rows returned by
  `recent_events()`.
- Filter build timestamps continue to use existing release metadata.
- Readiness content uses the existing guardrail readiness result and diagnostics.
  Its decision logic is unchanged.

## Calculations

- Total, approved, and pending counts are calculated from current domain rows.
- Unique vendor, category, and filter counts ignore empty values.
- Average confidence is the arithmetic mean of current confidence values,
  rounded to one decimal place.
- Low confidence uses the existing UI band boundary: scores below 50.
- Top distributions use the five most common values. Empty distribution values
  are presented as `Unknown` and localized by the template. Percentages are
  calculated against total domain rows and rounded to one decimal place.
- Readiness presentation is `ready`, `insufficient_data`, or `failed`. Evidence
  gaps are presentation-only and do not modify the underlying readiness result.

## Operational activity

The latest audit entries are selected for filter build, validation, system
doctor, and intelligence check. Duration, issue count, and exit code are shown
only when those values already exist in event details. Missing operations show a
clear no-data state.

## Test-data display filtering

Production presentation ignores audit events containing `/tmp/pytest-`, the
Windows-equivalent temporary marker, or the known test values `example.test`,
`buildfail.test`, and `approve.test`. Filtering is disabled while Flask is in
testing mode. The audit file is never changed or deleted.
