# v2.0.1 Authentication UX Fixes

## Problem

Public read-only pages exposed mutation controls to guests and viewer accounts.
The server correctly rejected those operations, but a guest without a CSRF token
received a misleading session-expiry response. A small set of policy explanation
phrases could also appear in English in the Arabic interface.

## Cause

Server-side RBAC and CSRF enforcement were complete, while template visibility
did not mirror the route roles. CSRF validation also ran before the authentication
decorators could redirect an anonymous user.

## Changes

- Sensitive controls now render only for their route's actual roles.
- Admin-only controls cover deletion, builds, review decisions, approvals, and
  manual readiness approval.
- Admin/editor controls cover domain creation/editing, analysis, validation,
  intelligence checks, and suggestion rejection where the existing route permits it.
- The navbar keeps a POST-only CSRF-protected logout form and displays
  `display_name` with a username fallback.
- Anonymous protected POST requests redirect to login with a same-origin,
  validated `next` value before CSRF expiry messaging.
- Authenticated requests without a valid CSRF token remain rejected with the
  localized session-expiry message.
- Fixed descriptive policy phrases are translated at presentation time; stored
  technical values are unchanged.

## New behavior

- Guests and viewers retain the existing public read-only pages without mutation
  controls.
- Editors see only operations accepted by existing admin/editor routes.
- Admins see all applicable controls.
- `GET /logout` returns 405; valid logout remains POST plus CSRF.
- External redirect targets are rejected.

## Tests

`tests/test_web_auth_ux_v201.py` covers navbar states, role-aware controls,
POST-only logout, CSRF behavior for guests and signed-in users, safe redirects,
public read access, and targeted Arabic translations. Existing security tests
were updated only where the required anonymous POST behavior intentionally
changed from 400 to a login redirect.

## Unchanged

The domain database, database schema, Analyzer, Knowledge Engine, API, route
names, public read policy, release artifacts, CSRF strength, and RBAC decorators
were not changed.
